# 2026-11-07

## 小程序前端选型建议（蓉宠 V1.4）
- 通读了 README、doc/V1.4确认需求.md、V1.4开发与接入说明.md、prototype/index.html 与后端关键代码（SaTokenConfig、AppAuthController、FileUploadController、PayInitVO、application.yaml）。
- 结论：采用**微信原生小程序 + TypeScript**，不用 uni-app。理由：后端 `/app/v1/**` 全为微信专属能力（WxJava、微信支付 V3、手机号、订阅消息、msgSecCheck），多端跨端无收益；原型是 HTML + 字符串模板渲染，WXML/WXSS 属"逐页搬运"。
- 备选：如有 H5/抖音计划选 Taro 4；uni-app 仅在团队强 Vue 且确需多端时考虑。
- 脚手架：开发者工具 TS+Sass 模板 + tdesign-miniprogram + miniprogram-api-typings + openapi-typescript（用已有 springdoc `/v3/api-docs/app` 生成类型）。
- 发现的对接缺口（尚未修改代码）：①`WxLoginRequest` 只有 code，缺手机号授权接口（getPhoneNumber 返回 code，需 `/app/v1/auth/phone`）；②支付 mock 时 `PayInitVO.paid=true` 前端需跳过 `wx.requestPayment`；③上传单张、字段名 `file`；④COS 预签名 600s 过期需前端 onError 重取；⑤会话是 HTTP 拉取非 WebSocket；⑥服务端分享海报/小程序码未实现。
- 用户自述：后端开发，前端不熟（需"推广页/H5/落地页"这类概念的入门解释）。讲解保持大白话＋生活类比。
- **最终决定：小程序前端采用 uni-app（Vue3 + Vite + TS），推翻上条原生建议。** 后续按 uni-app 路线给方案，不再劝返。
- 本机环境实测（2026-11-07）：node v22.22.2 ✅（uni-app 要求 18+）、git 2.51.1 ✅、微信开发者工具**未安装** ❌（注册表只有"微信"）、PowerShell 下 `npm.ps1` 被执行策略拦截（需用 npm.cmd 或改 RemoteSigned）。
- uni-app 官方 CLI 模板：`npx degit dcloudio/uni-preset-vue#vite-ts <dir>`，运行 `npm run dev:mp-weixin`，产物 `dist/dev/mp-weixin`；升级编译器用 `npx @dcloudio/uvm@latest`。
- 规划前端目录：`D:\java\project\rong-pet-app`（与后端仓库并列，不塞进 Maven 工程）。
- 上线部署讨论：前端托管微信、服务器只跑后端；需域名+ICP备案+HTTPS（备案 2-3 周是关键路径）。服务器结论：2核4G 起步；首选阿里云 ECS u1 199元/年（企业认证、续费同价），备选腾讯云轻量 3年528；忌 38/68 秒杀款当生产、必须国内节点（境外无法备案）。
- 产出《doc/云服务器部署方案.md》：单机架构（nginx + Docker 同机 mysql8/redis7/app，COS 存储）、生产 docker-compose（不暴露 3306/6379、强密码、资源限制）、nginx 反代要点（X-Forwarded-Proto https、client_max_body_size 30m）、密钥清单、每日 mysqldump→COS 备份、上线 checklist、扩容触发线。
- 中间件结论：MySQL/Redis 同机 Docker 自部署（不买 RDS，省 700+/年），COS 复用腾讯云 ap-chengdu；内存账 OS 0.5G+MySQL 0.8G+Redis 0.128G+JVM 0.768G。
